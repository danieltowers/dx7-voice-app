# dx7-voice-app

A web app that sends Yamaha DX7 voices over Web MIDI into an instrument's edit
buffer: an original DX7, the DX7s, the DX7IID, the TX816, or Dexed. Browse a
voice library, tap a voice to send it, and edit it live with the controls.

**Open it:** <https://danieltowers.github.io/dx7-voice-app/>

- Use Chrome or Edge, on Android or a computer. Safari and every browser on an
  iPhone or iPad have no Web MIDI, so the app cannot send there.
- Tap **Load the starter voices** for a small library of voices made by the
  DX7 build agent.
- Add your own voices by opening `.syx` files: 32-voice banks from a DX7, a
  cartridge archive or Dexed's Save cart. They go under **My banks** and stay
  on your device; nothing is uploaded.
- **Help** in the app has the setup for each instrument. The
  [hardware page](https://danieltowers.github.io/dx7-voice-app/hardware.html)
  sends one fixed voice, to check the connection.

Install it from the browser's menu (Add to home screen, or Install app) and it
works offline. Edits live only in the instrument's edit buffer: nothing stored
on an instrument is changed.

This repository holds the published app only; it is built and published from
the `dx7-sound-builder-agent` project.

## The voice library file

This section is for developers. A library is one JSON file, written by
`tool/dx7 export-library` in `dx7-sound-builder-agent`. `starter-library.json`
is one too, generated by that project's `scripts/write_starter_library.py`. If
you edit it here, the next generator run overwrites your change, so make
lasting changes in the generator. `library.js` reads and checks the file.

### Top level

```json
{
  "version": 1,
  "exported": "2026-11-24",
  "fixture": { "voice": 0, "address": 1, "message": "<base64>" },
  "voices": [ ... ],
  "banks": [ ... ]
}
```

- `version`: the app reads version 1 only and refuses any other.
- `exported`: the date the file was written.
- `voices`: every distinct voice, each stored once.
- `banks`: the banks the library page lists, each pointing into `voices`.
- `fixture`: one complete MIDI message, for the load check described below.

### Voices

```json
{
  "name": "BRIGHTFL 1",
  "attribution": "confirmed",
  "designer": "dx7 build agent",
  "publisher": "2026-10-28-bright-fluegel",
  "voice": "SkoAAGNe…"
}
```

`voice` is base64 for the 155-byte unpacked single-voice parameter block
(VCED), the data a DX7 sends in a single-voice dump. It holds 6 operators of
21 parameters each (OP6 first), then the pitch envelope, algorithm, feedback,
LFO and transpose, then the 10-character name in ASCII. It is not the 128-byte
packed format used in 32-voice bulk dumps.

`attribution` is `confirmed`, `archive-attributed` or `unknown`. The page
shows it after `designer` and `publisher` as the slot's attribution line. An
entry may also carry `favourite` (`"love"` or `"like"`).

### Banks

```json
{
  "origin": "Starter banks",
  "folder": "2026-10-28-bright-fluegel",
  "file": "2026-10-28-bright-fluegel/bank.syx",
  "bank": 1,
  "name": "2026-10-28-bright-fluegel",
  "slots": [{ "voice": 0 }, { "voice": 1 }]
}
```

Banks hold no voice data. The library page groups them by `origin`, then by
`folder` (a cartridge or folder), then by bank. Each entry in `slots` is the
index of a voice in `voices`. A slot can also give its own `name` in place of
the voice's. A slot whose `voice` is `null` is listed but cannot be sent,
because its source holds a value a voice message cannot carry. `file` and
`bank` record where the bank came from. Together with `origin` they form the
bank's key, which the app uses to remember the last position and history. If
you rename any of the three, saved positions in that bank are lost.

### Sending and the fixture

To send a voice, the app wraps its 155 bytes in a single-voice SysEx message
(`voiceMessage` in `send.js`):

```
F0 43 0n 00 01 1B  <155 data bytes>  <checksum>  F7
```

Yamaha ID `43`, sub-status 0 with device number `n` (address 1 is `n = 0`),
format 0 (single voice), byte count `01 1B` (155), then the data, a checksum
and `F7`: 163 bytes in all. The instrument puts the voice in its edit buffer.

`fixture.message` is the exporter's own copy of that message for voice
`fixture.voice` at `fixture.address`. When a file loads, the app builds the
same message itself and compares it with the fixture byte for byte. If they
differ, it refuses the file, so the app and the exporter can never disagree
about the header or checksum and go on sending wrong data.
